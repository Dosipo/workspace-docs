# Как написать промпт

*Обновлено: 2 июля 2026 · Алсу*

Хороший промпт — это краткое техническое задание, а не длинная просьба. Модели нужны конкретные детали: листы, столбцы, критерии, форматы — иначе они выбирают параметры самостоятельно.

## 1. Начните с результата, входных данных, правил и формата

Опишите желаемый результат, источники данных, правила обработки и формат вывода.

**Плохой пример:** «Проанализируй запросы пользователей.»

**Лучший вариант:** «Составь сводку обращений в поддержку за июнь. Используй файл support_tickets.xlsx, лист "Тикеты", столбцы "Дата", "Тема", "Категория", "Приоритет", "Статус". Сгруппируй обращения по категории и приоритету, нерешённые покажи отдельно. Верни таблицу и краткое резюме из 5–7 предложений.»

**Проверка качества:** Если человек, незнакомый с процессом, сможет выполнить задачу по описанию — промпт хороший. Указывайте конкретные ячейки, листы, источники, а не общие фразы.

## 2. Не оставляйте важные решения умолчаниям

Явно задавайте критичные параметры: тип графика, сортировку, цвета, стиль, тон, структуру разделов, критерии релевантности, уровень детализации.

**Пример:** «Построй столбчатую диаграмму: ось X — категории обращений, ось Y — количество. Сортируй категории по убыванию числа. Используй один цвет для столбцов, подпиши значения над ними, без 3D-эффектов.»

## 3. Давайте примеры входных данных → результата

Примеры — один из самых мощных инструментов. Они показывают формат и логику решения.

**Пример:**
- Входные данные: Тема: Не могу войти | Приоритет: Высокий | Статус: Открыт
- Ожидаемый результат: Категория: Авторизация | Статус отчёта: Нерешено
- Логика: Обращение связано с авторизацией (проблема со входом). Статус "Открыт" = нерешённое обращение.

Для задач классификации смешивайте примеры разных классов, чтобы модель учила правило, а не порядок.

## 4. Для сложных задач укажите шаги

Разбивка многошаговых задач на этапы снижает потери данных:

1. Найди все обращения за июнь
2. Проверь полноту: дата, категория, приоритет, статус
3. Сгруппируй по категории и приоритету
4. Выдели нерешённые обращения
5. Верни таблицу, резюме и аудит качества

**Техника «шаг назад»:** Сначала сформулируй критерии срочности, затем примени к данным.

## 5. Запрашивайте аудит качества

Добавьте проверку полноты файлов и таблиц:

```
После результатов добавь аудит качества:
- Количество строк на входе
- Количество обработанных строк
- Пропущенные значения в обязательных столбцах
- Исключённые строки и причины
- Спорные решения
```

Если результаты нестабильны, уточните конкретное слабое место, а не весь промпт.

## 6. Используйте шаблон промпта

```
Задача: {что получить и зачем}
Входные данные: {файл / лист / столбцы / источники}
Правила: {отбор, группировка, сортировка, сокращение, проверка}
Формат результата: {таблица / список / JSON / Markdown / график}
Структура: {столбцы или разделы}
Пример:
  Вход: {короткий пример}
  Результат: {ожидаемый результат}
  Логика: {почему}
Проверка качества: {что проверить}
```

Роль и контекст можно добавить, но они не заменяют данные и правила.

## 7. Попросите модель задать вопросы перед выполнением

Для сложных задач помогает начать с уточнений: «Перед выполнением задай до 5 уточняющих вопросов, если они нужны для точности. Если информации достаточно, перефразируй понимание задачи, затем выполни.»

## 8. Быстрые способы улучшить уже написанный промпт

Дайте черновик и инструкцию модели:

```
Изучи прикреплённую инструкцию. Улучши промпт для большей точности и воспроизводимости.
Не меняй суть. Если информации не хватает, сначала задай вопросы.
Промпт: {текст}
```

Проверьте новую версию на 2–3 примерах, чтобы найти ошибки.

**ИИ для ИИ:** Модели пишут хорошие промпты. Дайте им требования:

```
На основе требований напиши промпт для ИИ. Компактный формат: без лишних объяснений,
повторений и украшений. Только то, что влияет на качество.
```

Модель может выявить недостатки в требованиях: отсутствующие источники, нечёткие критерии, неопределённые форматы результата.
