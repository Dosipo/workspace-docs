# Как улучшить ответы ИИ

*Обновлено: 2 июля 2026*

## Четыре ключевые зоны риска при работе с ИИ

1. Слишком длинные чаты без своевременного сброса контекста
2. Слишком много сообщений в день
3. Слишком большие сообщения с избыточным входным контекстом
4. Нерациональный выбор дорогих моделей

## 1. Длинные сессии чата

**Проблема:** Пользователи ведут беседы слишком долго, не отделяя завершённые подтемы от новых вопросов.

**Почему это дорого:** Чем длиннее история чата, тем больше текста модель должна обработать.

**Решения:**
- Начинайте новый чат для завершённых подтем
- Не продолжайте старые беседы по инерции при смене темы
- Запрашивайте итоговые резюме и переносите их в новые чаты
- Не используйте один чат как бесконечный рабочий стол

## 2. Избыточные итерации задач

**Проблема:** Пользователи делят задачи на длинные серии коротких сообщений.

**Почему это дорого:** Каждое дополнительное сообщение требует повторной обработки накопленной истории.

**Решения:**
- Формулируйте полные задачи сразу
- Включайте в первое сообщение: цель, данные, ограничения, желаемый результат и формат
- Держите запросы в пределах ~500–1000 символов для стандартных задач
- Максимум 1500–2000 для сложных задач (если уже сжато)

## 3. Вставка избыточного текста

**Проблема:** Пользователи вставляют целые документы, длинные переписки, большие логи.

**Почему это дорого:** Больше сырого текста = больше входных токенов.

**Решения:**
- Не вставляйте полные документы — используйте вложения или функцию знаний
- Исключайте длинные логи, если конкретные фрагменты не нужны
- Предварительно фильтруйте контекст до релевантных выдержек

**Рекомендуемые объёмы вставки:**
- 1000–2000 символов
- До 3000–5000 допустимо, если это действительно один нужный фрагмент
- Свыше 5000 символов: сократите, прикрепите как документ или используйте базу знаний

## 4. Выбор дорогих моделей для рутинных задач

**Проблема:** Дорогие модели используются сверх обоснованных требований задачи.

**Решения:**
- Начинайте рутинные, поисковые, справочные и черновые задачи с компактных моделей
- Переключайтесь на мощные модели только когда задачи действительно требуют глубокого анализа

### Когда использовать крупные модели
- Сложный анализ
- Многошаговое рассуждение
- Содержательные выводы и рекомендации
- Обработка больших неструктурированных материалов
- Подготовка финальных версий важных документов
- Сложный код, архитектура или исследовательские задачи
- Сценарии с высокой ценой ошибки

### Когда использовать компактные модели
- Стандартная аналитика
- Деловая переписка
- Резюмирование
- Подготовка черновиков
- Структурирование материалов
- Извлечение фактов
- Сравнение вариантов
- Перефразирование и редактирование
- Быстрые справочные запросы
- Простая классификация

## Правила качества запросов

Структурируйте все запросы по:
1. **Цель:** что именно нужно выполнить
2. **Контекст:** только действительно необходимые данные
3. **Ограничения:** важные соображения и исключения
4. **Формат ответа:** таблица, список, письмо, резюме, план, рекомендации и т.д.

### Ориентиры по длине запроса
- До 500 символов: короткий запрос для простой задачи
- 500–1000 символов: стандартный рабочий запрос
- 1000–2000 символов: допустимо для сложного задания (если сжато)
- Заметно длиннее 2000: проверьте на лишний контекст
- Свыше 3000 символов: обычно не следует отправлять как обычный текст в чат

## Признаки неэффективности

Пересмотрите подход, если замечаете:
- Один чат слишком долго ведётся со многими подтемами
- Разрешение задачи через десятки коротких обменов
- Вставка полного текста документа в чат
- Регулярная отправка больших логов, переписок или листингов кода
- Использование дорогой модели по умолчанию для рутинной работы
- Сочетание: длинный чат + много итераций + большой входной текст
- Текст запроса заметно длиннее одного экрана ввода без очевидной необходимости

## Пять ключевых правил

1. Не ведите бесконечные чаты
2. Не дробите задачи без необходимости
3. Не вставляйте большие неотфильтрованные тексты
4. Не выбирайте дорогие модели без причины
5. Начинайте с кратких, структурированных, полных запросов
