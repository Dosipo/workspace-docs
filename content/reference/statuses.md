## Встроенные статусы

| Ключ | Категория | Описание |
|---|---|---|
| `backlog` | unstarted | Задача отложена. Агент назначен, но запуск не происходит до перевода в `todo`. |
| `todo` | unstarted | Готова к выполнению. Назначенный агент будет запущен. |
| `in_progress` | started | Ведётся работа. |
| `in_review` | started | Ожидает проверки человеком. PR открыт или работа завершена и ждёт приёмки. |
| `blocked` | started | Работа приостановлена — есть зависимость или проблема, требующая разрешения. |
| `done` | terminal | Работа принята. |
| `cancelled` | terminal | Задача закрыта без выполнения. |

## Кастомные статусы воркспейса

### `agent_review`

**Категория lifecycle:** started

**Назначение:** задача проходит автоматизированное ревью агентом (QA-агент, security-агент или другой специализированный агент). Участие человека на этом этапе не требуется.

**Отличие от `in_review`:** `in_review` означает ожидание оценки человеком; `agent_review` означает, что проверку ведёт агент без участия человека.

**Типичный сценарий использования:**
```
in_progress → agent_review → in_review → done
```
или для задач без ревью человеком:
```
in_progress → agent_review → done
```

**Переходы:**
- В статус переводит агент, завершивший реализацию и передавший задачу на автоматическое ревью.
- Из статуса выходит агент-ревьюер: в `in_review` (нужна проверка человека), `done` (ревью пройдено), `blocked` (найдена проблема), `in_progress` (возврат на доработку).

**Использование в CLI:**
```bash
multica issue status <issue-id> agent_review
```

> **Примечание для агентов:** `agent_review` — кастомный статус; встроенная автоматика (`backlog`-паркинг, `in_review`-завершение) к нему не применяется. Для управления workflow используйте явные переходы через CLI.
