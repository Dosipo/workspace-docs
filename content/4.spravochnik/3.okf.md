## Что такое OKF

Open Knowledge Format — открытая спецификация, не привязанная к вендору. Она превращает паттерн «LLM-wiki» (gist Андрея Карпаты) в переносимый формат, который читают и агенты, и люди.

Бандл OKF — это каталог markdown-файлов с YAML frontmatter. SDK, рантайм и платформа не нужны: файлы открываются в любом редакторе, лежат в git и рендерятся на GitHub.

## Какую проблему решает

Знания разбросаны по каталогам данных, викам, комментариям в коде и ноутбукам. Подходы вроде Obsidian, `AGENTS.md` / `CLAUDE.md` и metadata-as-code несовместимы между собой. Авторы предлагают не ещё один сервис, а общий **формат**.

Принципы:

1. **Минимум требований.** Обязательно только поле `type`.
2. **Независимость производителя и потребителя.** Формат — это контракт, инструменты по обе стороны заменяемы.
3. **Формат, а не платформа.** Нет привязки к облаку, БД, модели или агентному фреймворку.

## Как устроен бандл

Один концепт (таблица, датасет, метрика, ранбук, API) — один файл. Идентификатор концепта (Concept ID) — путь к файлу внутри бандла без суффикса `.md`: для `tables/orders.md` это `tables/orders`. Обычные markdown-ссылки между концептами образуют граф.

- `index.md` — необязательный оглавляющий файл для постепенного раскрытия (progressive disclosure).
- `log.md` — необязательная хронология изменений: секции по датам `YYYY-MM-DD`, новые сверху.

```text
sales/
├── index.md
├── tables/
│   ├── index.md
│   ├── orders.md
│   └── customers.md
└── metrics/
    └── weekly_active_users.md
```

## Поля frontmatter

::field-group
  ::field{name="type" type="string" required}
  Единственное обязательное поле. Тип концепта в свободной форме, например `BigQuery Table`.
  ::

  ::field{name="title" type="string"}
  Отображаемое имя.
  ::

  ::field{name="description" type="string"}
  Краткое описание в одно предложение.
  ::

  ::field{name="resource" type="string"}
  URI исходного ресурса. Для абстрактных концептов не указывается.
  ::

  ::field{name="tags" type="string[]"}
  Короткие теги.
  ::
::

```md [tables/orders.md]
---
type: BigQuery Table
title: Orders
description: One row per completed customer order.
resource: https://console.cloud.google.com/bigquery?p=acme&d=sales&t=orders
tags: [sales, revenue]
---
Joined with [customers](/tables/customers.md) on `customer_id`.
```

В v0.1 из статьи также было поле `timestamp` — время обновления.

## Что изменилось в v0.2

Спецификация переехала в репозиторий [GoogleCloudPlatform/open-knowledge-format](https://github.com/GoogleCloudPlatform/open-knowledge-format); старая папка `okf/` в `knowledge-catalog` — замороженный снимок.

- **Заменено:** `timestamp` → `generated.at`; список `# Citations` в теле → поле `sources`.
- **Добавлено:** `generated`, `verified`, `status` (`draft` / `stable` / `deprecated`), `stale_after`, тип `Attested Computation`.
- **Версия:** корневой `index.md` может объявить `okf_version: "0.2"`.

::tip
Дополнительные ключи frontmatter допустимы, а `timestamp` потребитель может читать как legacy-замену `generated.at`, если `generated` нет.

Наш шаблон страниц (см. [правила оформления](/nachalo-raboty/onboarding/authoring)) пока не следует рекомендациям v0.2: он использует `generated: human-authored` вместо объекта `generated: {by, at}` и `status: current` вместо `draft`, `stable` или `deprecated`. Спецификация считает ограничения необязательных полей мягкими, но миграцию шаблона нужно согласовать отдельно.
::

## Референсные реализации

- Агент обогащения для BigQuery: описывает каждую таблицу и view, затем второй проход LLM добавляет ссылки и join-пути.
- Статический HTML-визуализатор: рисует граф бандла в одном файле без бэкенда.
- Три примера бандлов: GA4 e-commerce, Stack Overflow, Bitcoin.

Google Cloud Knowledge Catalog умеет загружать OKF и отдавать его агентам Google.
