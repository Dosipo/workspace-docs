Страница описывает актуальную версию Open Knowledge Format — **v0.2**. Прочитайте её, чтобы понимать, как устроен бандл, какие поля frontmatter обязательны и как записывать происхождение и достоверность знаний.

Источник — [SPEC.md](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/main/SPEC.md) в репозитории `GoogleCloudPlatform/open-knowledge-format`. Контекст появления формата — в [статье Google Cloud](#контекст-статья-google-cloud-и-v01) про v0.1.

## Что такое OKF

OKF представляет знания (метаданные, контекст, выверенные сведения) как каталог markdown-файлов с YAML frontmatter. Реестр, центральный орган и специальные инструменты не нужны. Формат удобен людям, разбирается агентами, хорошо отображается в диффах и переносится между системами.

Цели: универсальный формат для производителей знаний, рекомендации для потребителей, обмен между организациями и небольшой набор полей о доверии.

Не цели: фиксированная таксономия типов, инфраструктура хранения и запросов, замена схем вроде Avro или OpenAPI (OKF ссылается на них), стандарты упаковки кода исполнителей.

## Бандл и концепты

- **Бандл** — самодостаточное иерархическое дерево markdown-файлов и единица поставки. Раскладку каталогов выбирает производитель.
- **Концепт** — один markdown-документ об одной единице знания (таблица, метрика, ранбук, API).
- **Concept ID** — путь к файлу внутри бандла без суффикса `.md`. Для `tables/orders.md` это `tables/orders`.

Бандл распространяют как git-репозиторий (рекомендуется), tar/zip или подкаталог большого репозитория. Теги задаются только полем `tags`: отдельного файла тегов нет.

```text [Пример бандла]
sales/
├── index.md
├── tables/
│   ├── index.md
│   ├── orders.md
│   └── customers.md
├── metrics/
│   └── weekly_active_users.md
└── log.md
```

::note
Имена `index.md` и `log.md` зарезервированы и не могут быть концептами. Любой другой `.md`-файл — концепт.
::

## Frontmatter концепта

Концепт — UTF-8 markdown-файл с блоком YAML frontmatter и свободным телом.

::field-group
  ::field{name="type" type="string" required}
  Единственное обязательное поле, непустая строка: `BigQuery Table`, `Metric`, `Playbook`, `Attested Computation`. Типы не регистрируются централизованно; потребитель обязан терпеть неизвестные типы.
  ::

  ::field{name="title" type="string"}
  Рекомендуется. Отображаемое имя; потребитель может вывести его из имени файла.
  ::

  ::field{name="description" type="string"}
  Рекомендуется. Одно предложение для индексов и сниппетов.
  ::

  ::field{name="resource" type="string"}
  Рекомендуется. URI исходного ресурса. Для абстрактных концептов не указывается.
  ::

  ::field{name="tags" type="string[]"}
  Рекомендуется. Список коротких строк.
  ::
::

Производитель может добавлять любые другие ключи. Потребитель должен сохранять неизвестные ключи и не вправе отвергать из-за них документ.

Тело — обычный markdown. Предпочитайте структуру (заголовки, списки, таблицы, блоки кода) прозе. Разделы не обязательны; принятые заголовки — `# Schema`, `# Examples`, `# Computation`.

```yaml [tables/orders.md]
---
type: BigQuery Table
title: Orders
description: One row per completed customer order.
resource: https://console.cloud.google.com/bigquery?p=acme&d=sales&t=orders
tags: [sales, revenue]
generated: { by: reference_agent/gemini-2.5-pro, at: 2026-05-28T14:30:00Z }
status: stable
---
```

## Происхождение, доверие и жизненный цикл

Все поля этого раздела необязательны. Концепт без них считается непроверенным, но не отвергается. Все метки времени — ISO 8601 с явным смещением UTC, например `2026-06-30T14:00:00Z`.

::field-group
  ::field{name="sources" type="object[]"}
  Материалы, из которых получен концепт. В каждой записи обязателен `resource` — ссылка на артефакт (URL, путь в бандле, путь в `references/`) или описание области, на которую нельзя перейти («все запросы в проекте X»). Необязательно: `id` (ключ для сносок; указывайте, если тело ссылается на источник), `title`, `author` (в формате актора), `usage_count`, `last_modified`. Окно `usage_window: {from, to}` задаётся один раз рядом с `sources`; запись может его переопределить.
  ::

  ::field{name="generated" type="object"}
  Как создано текущее содержимое: `{ by, at }`. `by` обязателен и записывается как актор. `at` — время последнего значимого изменения содержимого.
  ::

  ::field{name="verified" type="object[]"}
  Список событий проверки `{ by, at }`. Несколько записей — независимые проверки; актуальность определяет последняя `at`. Одиночный объект допустим, и потребитель обязан считать его списком из одного элемента. Не зависит от `generated.at`.
  ::

  ::field{name="status" type="string"}
  `draft` — не проверен или не завершён; `stable` — готов к использованию; `deprecated` — оставлен ради ссылок и истории. Без поля подразумевается `stable`.
  ::

  ::field{name="stale_after" type="datetime"}
  Абсолютный момент. Концепт устарел, когда текущее время равно этому моменту или позже.
  ::
::

OKF не хранит оценку достоверности: оценки субъективны и быстро устаревают. Вместо неё записывают объективные сигналы (`author`, `usage_count`, `last_modified`). `usage_count` груб: читайте его как признак «жив или мёртв» и тренд, а не как точный рейтинг.

Для атрибуции отдельных утверждений используйте сноски, метка которых совпадает с `sources[].id`, например `[^ga4-schema]`. Метки выбраны вместо номеров, потому что агенты переупорядочивают списки и позиционные индексы дают ложную атрибуцию.

### Уровни доверия

Потребитель выводит уровень из `verified`:

| Условие | Уровень |
| --- | --- |
| Ключа `verified` нет | Непроверен (unverified) |
| Все проверяющие не `human:` | Подтверждён машиной (machine-confirmed) |
| Есть хотя бы один `human:<id>` | Проверен человеком (human-reviewed) |

Уровни носят справочный характер и не управляют доступом.

### Акторы

- Агенты и инструменты: `<producer>/<version>`, например `reference_agent/gemini-2.5-pro`.
- Люди: `human:<id>`. Префикс обязателен для написанного или подтверждённого человеком содержимого.
- Автоматические процессы: `process:<id>`.

## Ссылки и пути

Концепты ссылаются друг на друга обычными markdown-ссылками; вместе они образуют граф.

- **Абсолютная ссылка** начинается с `/` и считается от корня бандла. Рекомендуется: не ломается при переносе документов.
- **Относительная ссылка** — обычный путь вроде `./other.md`.
- Ссылка задаёт связь без типа; смысл передаёт окружающий текст.
- Потребитель обязан терпеть битые ссылки: они могут вести на ещё не написанные знания.

Поля `resource`, `sources[].resource`, `computation`, `executor.resource` и `attester.resource` принимают абсолютный URL, путь с `/` или относительный путь. Подкаталог `references/` по соглашению хранит зеркала внешних материалов.

## index.md и log.md

**`index.md`** может лежать в любом каталоге и перечисляет его содержимое для постепенного раскрытия (progressive disclosure).

- Frontmatter нет; исключение — корневой индекс, где можно объявить версию: `okf_version: "0.2"`.
- В теле — разделы с записями `* [Заголовок](url) - описание`. Запись о подкаталоге ведёт на `subdir/`.
- Записи желательно дополнять `description` концепта. Производитель может генерировать индекс автоматически, а потребитель — собрать его сам, если файла нет.

**`log.md`** может лежать на любом уровне и хранит историю изменений.

- Плоский список секций по датам, новые сверху, под заголовком вроде `# Directory Update Log`.
- Заголовки дат обязаны иметь вид `## YYYY-MM-DD`.
- Записи — проза, например `* **Update**: ...`. Ведущее жирное слово (Update, Creation, Deprecation) — лишь соглашение.

## Attested Computation

Это тип концепта, который хранит санкционированный способ вычислить значение, чтобы потребитель мог проверить, что выполнялось именно оно. OKF описывает вычисление и способ проверки, но сам ничего не выполняет.

::field-group
  ::field{name="runtime" type="string" required}
  Обязательно для этого типа. Среда выполнения (`bigquery`, `postgres`, `dbt`, `python`, `Looker`); определяет, как читать `parameters`.
  ::

  ::field{name="parameters" type="object[]"}
  Типизированные «дыры», которые заполняет агент: `{ name, type, required }`.
  ::

  ::field{name="computation" type="string"}
  Путь к файлу с вычислением. Если его нет, вычислением считается блок под заголовком `# Computation` в теле.
  ::

  ::field{name="executor" type="object"}
  `resource` — инструкции или код запуска; `receipt` — поля, которые обязан вернуть запуск (например, `job_id`, `executed_sql`).
  ::

  ::field{name="attester" type="object"}
  `resource` — детерминированный код без LLM, который принимает квитанцию и выдаёт вердикт. Предполагается запуск на стороне потребителя.
  ::
::

Агент может только подставлять значения параметров и не вправе писать или менять само вычисление. Квитанции и вердикты — артефакты времени выполнения и в бандле не хранятся.

::tip
`verified` подтверждает, что определение соответствует политике: оно относится к документу, медленное и хранится. Аттестация подтверждает, что конкретный запуск дал значение санкционированным способом: она относится к вызову и не хранится. Нужны обе.
::

## Соответствие спецификации

Бандл соответствует v0.2, если:

1. У каждого незарезервированного `.md`-файла есть разбираемый YAML frontmatter.
2. В каждом frontmatter есть непустой `type`.
3. Любые `index.md` и `log.md` следуют правилам выше.

Потребитель не вправе отвергать бандл или концепт из-за отсутствия необязательных полей, неизвестных типов и ключей, битых ссылок или отсутствия индексов. Остальные ограничения — мягкие рекомендации.

## Контекст: статья Google Cloud и v0.1

[Статья «Introducing the Open Knowledge Format»](https://cloud.google.com/blog/products/data-analytics/how-the-open-knowledge-format-can-improve-data-sharing) вышла 12 июня 2026 года в блоге Google Cloud (Data Analytics). Авторы — Sam McVeety и Amir Hormati из команды Data Cloud. Она описывает **v0.1**.

OKF превращает паттерн «LLM-wiki» ([gist Андрея Карпаты](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)) в переносимый формат. Проблема, которую решает статья: знания разбросаны по каталогам данных, викам, комментариям в коде и ноутбукам, а подходы вроде Obsidian, `AGENTS.md` / `CLAUDE.md` и metadata-as-code несовместимы между собой. Авторы предлагают не ещё один сервис, а общий формат.

Принципы из статьи:

1. **Минимум требований** — обязателен только `type`.
2. **Независимость производителя и потребителя** — формат служит контрактом, инструменты по обе стороны заменяемы.
3. **Формат, а не платформа** — нет привязки к облаку, БД, модели или фреймворку.

Референсные реализации из статьи: агент обогащения для BigQuery, статический HTML-визуализатор графа и три примера бандлов (GA4 e-commerce, Stack Overflow, Bitcoin). Google Cloud Knowledge Catalog умеет загружать OKF и отдавать его агентам Google.

### Что изменилось между v0.1 и v0.2

| Область | v0.1 (статья) | v0.2 (SPEC.md) |
| --- | --- | --- |
| Время | поле `timestamp` | `generated.at`; `timestamp` потребитель может читать как запасной вариант, только если `generated` отсутствует |
| Источники | список `# Citations` в теле | поле `sources` во frontmatter; старые списки можно разбирать |
| Доверие и жизненный цикл | нет | `verified`, `status`, `stale_after`, акторы |
| Вычисления | нет | тип `Attested Computation` |
| Версия | не объявляется | `okf_version` в корневом `index.md` |

Остальное перешло без изменений. Репозиторий `knowledge-catalog/tree/main/okf` с примерами бандлов — [замороженный снимок](https://github.com/GoogleCloudPlatform/knowledge-catalog/tree/main/okf); спецификация поддерживается в [open-knowledge-format](https://github.com/GoogleCloudPlatform/open-knowledge-format).

## Наш шаблон и v0.2

Шаблон frontmatter страниц этой базы (см. [правила оформления](/nachalo-raboty/onboarding/authoring)) пока не следует рекомендациям v0.2:

- `generated: human-authored` вместо объекта `generated: { by, at }`;
- `status: current` вместо `draft`, `stable` или `deprecated`;
- `timestamp` вместо `generated.at`.

::note
Эти значения отклоняются от рекомендаций v0.2. Для необязательных полей спецификация рекомендует мягкую обработку ограничений, но не гарантирует, что любой потребитель примет некорректные значения известных полей. Миграцию шаблона нужно согласовать отдельно.
::
