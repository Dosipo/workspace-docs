Голденсет — небольшой закрытый набор «вход → эталон или критерий» под вашу задачу и ваши данные. После этой страницы вы соберёте такой набор и будете запускать его при каждой смене модели или промпта.

От публичных бенчмарков он отличается тем, что отражает реальное распределение ваших запросов, не попал в обучение моделей, версионируется вами и привязан к вашим критериям качества. Официального стандарта нет, ниже общепринятая практика.

## Процесс

```flow
title: Жизненный цикл голденсета
collect [start] Сбор примеров
  | Реальные обезличенные запросы, краевые случаи, известные провалы.
label [actor] Разметка и эталоны
  | Два разметчика, инструкция, рубрика или точный ответ.
version [service] Версия в git
  | Файл, version, changelog, canary-строка.
run [service] Прогон
  | Старая и новая конфигурация с одинаковыми параметрами.
judge [service] Оценка
  | Код, LLM-as-judge, выборочная проверка человеком.
report [end] Отчёт
  | Метрики и список примеров, где стало хуже.
collect -> label : отобрать
label -> version : зафиксировать
version -> run : запустить
run -> judge : ответы
judge -> report : оценки
report ..> collect : добавить новые провалы
```

## Как собрать

::steps
### Возьмите примеры из реальной работы

Начните с реальных запросов или документов после обезличивания, затем добавьте краевые случаи и известные провалы. Синтетику допустимо добавлять, но помечайте её и проверяйте вручную.

### Разметьте

Привлеките двух разметчиков и разрешайте расхождения. Измеряйте согласованность (коэффициент Cohen's κ). Короткая инструкция разметки — часть датасета.

### Задайте эталон

Выберите точный ответ (число, класс, JSON) или рубрику критериев, например «есть ссылка на пункт договора» и «не выдумана сумма».

### Определите размер

Стартуйте с 30–50 примеров, цельтесь в 100–300. Учитывайте доверительный интервал: на 100 примерах при точности 50% он составляет примерно ±10 процентных пунктов (оценка по биномиальной формуле).

### Версионируйте

Храните файл в git с полем `version` и changelog. Не правьте эталоны задним числом без новой версии. Сохраняйте прогоны: модель, промпт, дату.

### Защитите от утечки

Не публикуйте набор в открытом репозитории и не отправляйте в сервисы, которые обучаются на данных. Добавьте canary-строку, как GUID у Terminal-Bench. Держите закрытый hold-out, который не используется при подборе промптов.
::

```jsonl [goldenset/v1/cases.jsonl]
{"id": "inv-001", "input": "Сумма по счёту в письме ниже: ...", "expected": {"amount": 12500, "currency": "RUB"}, "tags": ["extraction"]}
{"id": "inv-002", "input": "Письмо без суммы: ...", "expected": {"amount": null}, "tags": ["edge", "no-hallucination"]}
```

## Как оценивать

- **Код — всегда первым выбором.** Точное совпадение, regex, проверка схемы JSON, исполнение кода или формулы.
- **LLM-as-judge — для свободного текста.** Судья смещён: к позиции ответа, к многословию, к своим ответам. [Исследование Zheng и др.](https://arxiv.org/abs/2306.05685) показало, что сильный судья согласуется с людьми более чем в 80% случаев на MT-bench и Arena.
- **Человек — на старте и при смене судьи.** Проверяйте выборочно (например, 10–20%) и все спорные случаи.

::tip
Калибруйте судью: разметьте людьми 50–100 примеров, сравните согласие и κ, меняйте порядок ответов, используйте рубрику. Судья должен быть другой моделью, чем оцениваемая.
::

## Регрессионный прогон

Запускайте голденсет перед сменой модели или промпта на старой и новой конфигурации с одинаковыми параметрами.

1. Сравните метрики с учётом доверительного интервала.
2. Посмотрите не только среднее, но и список примеров, где стало хуже.
3. Встройте прогон в CI.
4. Повторяйте по расписанию: вендор меняет версии моделей без вашего участия.

## Инструменты

| Инструмент | Суть |
|---|---|
| [Inspect (UK AISI)](https://inspect.aisi.org.uk) | Открытый фреймворк: набор данных, solver, scorer; более 200 готовых бенчмарков; оценка моделью, агенты, песочницы |
| [promptfoo](https://www.promptfoo.dev/docs/red-team/) | CLI для тестов промптов и red teaming, конфиг в YAML, интеграция в CI |
| OpenAI Evals | Фреймворк и реестр оценок от OpenAI; статус поддержки не проверен |
| DeepEval | Python-фреймворк метрик в стиле pytest |
| Ragas | Метрики для RAG: faithfulness, context precision и recall, answer relevancy |
| LangSmith | Платформа LangChain: датасеты, прогон оценок, трассировка |

::note
Описания OpenAI Evals, DeepEval, Ragas и LangSmith даны по общим знаниям и не сверены с документацией. Проверьте их перед внедрением.
::

## Как применить у нас

- **Excel:** 50–100 реальных обезличенных таблиц или запросов с эталонами (число, формула, структура); оценка точным совпадением или проверкой формулы.
- **n8n:** проверяйте схему JSON на выходе LLM-узла кодом.
- **Конфиденциальные данные:** прогоните тот же голденсет на локальной модели и на облачных, сравните качество на своих данных. Модели — в [Списке моделей](/spravochnik/modeli).
- **Смена модели:** обязателен прогон голденсета; храните результаты рядом с версией набора.

Публичные бенчмарки для первичного отбора кандидатов — на странице [Бенчмарки качества](/praktiki/ocenka-modeley/benchmarki-kachestva).
