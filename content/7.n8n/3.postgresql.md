# Работа с PostgreSQL в n8n

*Обновлено: 29 июня 2026*

## Что нужно перед запуском

### Credentials

- Для всех PostgreSQL-нод используйте credential **«Postgre n8n»** (общий credential для подключения к PostgreSQL)
- Для нод эмбеддингов используйте **«BaseGeotechModelCreds»** (для модели `geotech/openai/text-embedding-3-small`)

Если после импорта workflow нода показывает ошибку credentials — откройте каждую PostgreSQL-ноду и выберите «Postgres n8n».

## Пример 1: Создание таблицы и загрузка данных

**Ссылка на workflow:** https://n8n.geotech.user.events/workflow/mfFVSJ2CSQFRrE52

Workflow создаёт таблицу `n8n_demo_dragons` и загружает 5 строк данных.

**Основные поля таблицы:**
- `dragon_id` — идентификатор дракона
- `dragon_name` — имя
- `epithet` — эпитет
- `habitat` — место обитания
- `favorite_food` — любимая еда
- `age_years` — возраст
- `abilities` — описание способностей
- `full_text` — текст для эмбеддингов и поиска
- `embedding` — векторное поле, изначально пустое

**Как запустить:**
1. Перейдите по ссылке на workflow или импортируйте как JSON
2. Убедитесь, что все PostgreSQL-ноды используют credential «Postgres n8n»
3. Запустите последнюю ноду «Check embedding field», нажав ▶
4. Откройте вывод ноды «Check data in table»

**Ожидаемый результат:** 5 строк в таблице `n8n_demo_dragons`; поле embedding пустое.

Workflow можно запускать повторно — записи обновляются по `dragon_id`, а не дублируются.

## Пример 2: Загрузка векторных embeddings

**Ссылка на workflow:** https://n8n.geotech.user.events/workflow/mj5QYpdDY9rP98fP

Workflow создаёт векторное представление из текста поля `full_text` и записывает его в поле `embedding`.

### Вариант 1: Запись embedding в отдельную таблицу

Целевая таблица: `n8n_demo_dragons`, поле `embedding`.

Подходит для сценариев, когда данные должны оставаться в доменной таблице (каталоги объектов, справочники, карточки товаров).

**Логика:**
1. Workflow выбирает строки `n8n_demo_dragons` где `embedding IS NULL`
2. Берёт текст из поля `full_text`
3. Временно записывает embeddings в `n8n_vectors` (через PGVector ноду)
4. SQL переносит вектор в `n8n_demo_dragons.embedding`
5. Временные строки из `n8n_vectors` удаляются

### Вариант 2: Запись embedding в общую таблицу

Таблица хранит:
- `text` — текст строки или фрагмента
- `metadata` — описание источника, `dragon_id`, имя, путь, коллекция
- `embedding` — векторный embedding
- `collection_id` — ссылка на коллекцию

## Порядок запуска

1. Сначала запустите «Пример PostgreSQL. Создание таблицы и загрузка данных»
2. Убедитесь, что в «Check data in table» отображаются 5 драконов
3. Затем запустите нужную ветку «Пример PostgreSQL. Загрузка векторных embeddings»

## Проверка результатов

Для таблицы `n8n_demo_dragons`:
```sql
SELECT
  COUNT(*) AS total_rows,
  COUNT(embedding) AS rows_with_embedding
FROM n8n_demo_dragons;
```

**Ожидаемый результат для демо-набора:** 5 строк с непустым embedding.
