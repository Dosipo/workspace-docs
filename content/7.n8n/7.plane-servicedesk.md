# Интеграция PLANE → Сервис Деск

Workflow автоматически опрашивает PLANE API каждые 5 минут и переносит задачи с меткой `needs-human` в сервис деск. Результат обратно записывается в PLANE для дедупликации.

## Архитектура

```
PLANE (polling) → n8n → Service Desk
                    ↑
              writeback (external_id)
```

**Почему polling, а не webhooks**: локальный PLANE не имеет публичного URL для доставки webhooks. n8n опрашивает PLANE API сам — никаких входящих соединений не нужно.

## Flow workflow

| Шаг | Нода | Что делает |
|-----|------|-----------|
| 1 | Schedule Trigger | Запуск каждые 5 минут |
| 2 | Read State | Читает `lastRunTimestamp` и список обработанных ID из static data |
| 3 | Fetch PLANE Issues | `GET /api/v2/workspaces/{slug}/work-items/?label_id={needs-human}&updated_at__gte={ts}` |
| 4 | Deduplicate | Фильтрует уже синхронизированные задачи (по `external_id` и static data) |
| 5 | Map to Schema | Маппинг полей PLANE → схему сервис деска |
| 6 | Create SD Ticket | `POST /api/tickets` в сервис деске |
| 7 | Prepare Writeback | Извлекает `sd_ticket_id` из ответа |
| 8 | Write Back to PLANE | `PATCH /work-items/{id}/` — записывает `external_id` и `external_source: "servicedesk"` |
| 9 | Update Dedup State | Обновляет `processedIssues` в static data |
| 10 | Save Timestamp | Сохраняет `lastRunTimestamp = now()` для следующего цикла |

## Схема маппинга

```json
{
  "source": "plane",
  "plane_issue_id": "<uuid>",
  "plane_identifier": "PROJ-42",
  "title": "...",
  "description": "...",
  "priority": "urgent",
  "labels": ["needs-human"],
  "url": "https://plane.example.com/workspaces/..."
}
```

## Необходимые переменные окружения

Добавить в n8n → Settings → Environment Variables:

| Переменная | Описание | Пример |
|-----------|----------|--------|
| `PLANE_URL` | Базовый URL PLANE (без `/`) | `https://plane.geotech.user.events` |
| `PLANE_TOKEN` | Personal Access Token PLANE | `plane_pat_xxx...` |
| `PLANE_WORKSPACE_SLUG` | Slug воркспейса PLANE | `my-workspace` |
| `NEEDS_HUMAN_LABEL_ID` | UUID метки `needs-human` | `01234567-...` |
| `SERVICEDESK_URL` | Базовый URL сервис деска | `https://sd.example.com` |
| `SERVICEDESK_TOKEN` | API-токен сервис деска | `sd_token_xxx...` |

## Первоначальная настройка

### 1. Создать метку `needs-human` в PLANE

1. Открыть PLANE → Settings → Labels
2. Создать метку с именем `needs-human`
3. Скопировать UUID метки (виден в URL или через API)

Получить UUID через API:
```bash
curl -H "X-Api-Key: $PLANE_TOKEN" \
  "$PLANE_URL/api/v2/workspaces/$PLANE_WORKSPACE_SLUG/labels/" \
  | jq '.results[] | select(.name == "needs-human") | .id'
```

### 2. Добавить переменные окружения в n8n

Открыть n8n (`https://n8n.geotech.user.events`) → **Settings → Environment Variables** и добавить все переменные из таблицы выше.

Для авторизации n8n к PLANE можно также создать **credential** типа **Header Auth**:
- Name: `PLANE API`
- Name: `X-Api-Key`
- Value: `<your PLANE_TOKEN>`

### 3. Импортировать workflow в n8n

1. Открыть n8n → **Workflows → Import from file**
2. Выбрать файл [`plane-servicedesk-integration.json`](/n8n/plane-servicedesk-integration.json)
3. Сохранить и активировать workflow

### 4. Проверить первый запуск

1. Нажать **Execute Workflow** вручную
2. Убедиться, что нода **Fetch PLANE Issues** возвращает задачи (или пустой массив, если меток нет)
3. Проверить, что в сервис деске появился тикет
4. Проверить в PLANE, что у задачи заполнено поле `external_id`

## Дедупликация

Workflow использует два уровня дедупликации:

1. **`external_id` в PLANE** — если задача уже синхронизирована, PLANE API возвращает её с заполненным `external_id: "servicedesk"`. Нода Deduplicate пропускает такие задачи.
2. **Static data** — n8n хранит `processedIssues` (map `plane_issue_id → {synced, sd_ticket_id}`) между запусками. Защищает от повторной обработки в случае задержки writeback.

## Troubleshooting

**Workflow не запускается**
- Убедиться, что workflow активирован (переключатель Active в правом верхнем углу)
- Проверить логи в n8n → Executions

**PLANE API возвращает 401**
- Проверить переменную `PLANE_TOKEN` — токен должен иметь права на чтение задач
- Убедиться, что заголовок `X-Api-Key` передаётся правильно

**Тикеты дублируются**
- Проверить, что нода **Write Back to PLANE** успешно выполняется (статус 200)
- Посмотреть static data workflow в n8n → Workflow Settings → Static Data

**Задачи не попадают в выборку**
- Проверить `NEEDS_HUMAN_LABEL_ID` — UUID должен точно совпадать с меткой в PLANE
- Проверить, что задача обновлена после `lastRunTimestamp` (при первом запуске берётся -24h)
